## 0. 一分钟速览

**这是什么**：一个把 Android LLM 聊天客户端变成"设备端 Agent"的应用 —— 170+ 内置工具按需启用，支持工作流、定时任务、内置浏览器、SSH、子代理、MCP、Skills。

**技术栈**：Kotlin 2.4.20 · Jetpack Compose (Material 3) · MVVM · OkHttp/Ktor · kotlinx.serialization · Koin · Room/DataStore · Gradle 9.5 + AGP 9.3。

## 1. 隐式约定（**最容易踩的坑，先看这里**）

1. **领域模型与数据库实体是分离的。**
   `Conversation`（领域模型）↔ `ConversationEntity`（Room 实体）通过映射函数转换。**真正的映射实现是文件末尾的顶层函数**（名字以 `Impl` 结尾，例如 `conversationToConversationEntityImpl`），类内的同名方法**只是薄包装**。改映射时**别改错地方**。

2. **给会话加字段，必须同时落库。**
   会话级覆盖字段（工作区 / 工具白名单 / 步数上限等）如果只加在领域模型上，**执行时会丢失** —— 因为流程是「创建 → 落库 → 按 id 重新加载」。必须同时改：Entity 列 + 双向映射 + **数据库版本与自动迁移**，并补一条"实体往返"单测。否则症状是"回显有、实效无"。

3. **一个文件里可能有多个 ViewModel。**
   例如侧边栏文件里同时存在 `vm: ChatVM`（参数传入）与 `drawerVm: ChatDrawerVM`（内部创建）。**改调用前先确认用的是哪一个**，否则编译期才会暴露。

4. **工具面是"按名字排序 + 按需注入"的。**
   - 注入前按工具名排序：**顺序参与请求前缀**，排序是为了稳定命中提示缓存 —— 不要随意改动注入顺序。
   - 有"冷档"机制：未解锁的工具只发**空 schema**，避免 170+ 工具一次性吃满上下文。
   - 调用 `list_tools` / `get_tool_schema` 之外的冷工具时，可能先被要求取 schema（`tool_schema_not_loaded`），这是预期行为。

5. **工具错误有统一信封。**
   所有工具错误应走同一个实现（`ToolErrors`，字段 `error` / `detail` / 可选 `recovery` + 稳定 code）。**不要**在工具里手搓 JSON 错误对象。

6. **无人值守的会话走独立通道。**
   定时任务与子代理是 headless 会话：工具调用**自动批准**（没有人接审批弹窗），因此靠**工具白名单收敛** + 危险命令兜底来控制风险。改动这条链时要特别小心。

7. **子代理的每次派发是独立会话。**
   配置与模型可复用，**上下文不继承**；有超时与步数上限；默认只读工作区 + 工作区内读写，写/执行类工具需要显式放开。

8. **资源文案（`res/values*/strings.xml`）**：
   - **单引号必须写成 `\'`**，裸单引号会让资源编译直接失败；
   - 跨语言**占位符必须一致**（`%1$d` 之类）；
   - 新增文案要**补齐所有语言目录**。

## 2. 构建与验证

```bash
./gradlew :app:compileDebugKotlin                 # 快验证：只编主源码
./gradlew :app:testDebugUnitTest                  # 全量单元测试
./gradlew :app:assembleRelease -Pandroid.injected.build.abi=arm64-v8a   # 单架构出包（更快）
./gradlew :app:lintDebug                          # Android Lint
```

**注意**：
- Android 工具链（aapt2 / d8 / NDK）是 **x86_64 二进制** —— 在 arm64 容器里**无法**完成 Android 编译。若你的环境编不了，请把"编译验证"交给能编的机器，别在本地反复试。
- 只改 Kotlin 逻辑时，`compileDebugKotlin` 比 `assembleRelease` 快一个量级；**出包只在需要装机验证时做**。
- 首次运行 Gradle/测试可能命中缓存而"看起来很快"；要确认真跑了，用 `--rerun-tasks`。

- **公开面**：仓库内容（代码、注释、提交信息、文案、测试数据）**不得**出现内部信息 —— 内部路径、主机名、内网地址、个人标识、私有文档引用，以及任何凭证（token / 口令 / 私钥 / 签名文件）。
- 提交信息与代码里**不要**贴本机绝对路径（例如 SDK 目录、签名文件路径）。**注意**：Lint 基线文件（`lint-baseline.xml`）会把报错原文抄进去，其中可能夹带本机路径 —— 改动它之后请检查一遍。
- 资源文件不要提交 `.jks / .keystore / .pem / .key / .env` 之类；签名文件与口令一律不入库。
- 本项目在本地装了提交钩子（公开面 / 资源文案 / Kotlin 自检 / 工具 schema / UI 硬编码 / 半成品自查）。**被拦下时请修改内容，不要用 `--no-verify` 绕过。**
- 新 clone 不会带上钩子（钩子不入版本库），需要按团队说明补装。

## 4. 常见症状 → 对策

| 症状 | 多半是 | 对策 |
|---|---|---|
| 改了代码，"编译通过"但行为没变 | 编译的其实是旧代码（同步判据失效） | 先核对目标机器上的 HEAD 是否与你一致，再编译 |
| 会话级设置"显示已生效"，实际没生效 | 字段没落库（见 §1.2） | 检查 Entity 列 / 映射 / 迁移 / 往返测试 |
| 工具调用返回"工具不存在" | 该工具不在当前（会话级）工具白名单内 | 检查助手级 / 会话级 / 子代理级的作用域 |
| 冷工具第一次调用失败 | 需要先取 schema | 按提示调用 `get_tool_schema` 后重试 |
| 资源编译报引号错误 | `strings.xml` 里的裸单引号 | 写成 `\'` |
| 单测"通过"但没跑新用例 | Gradle 缓存 | 加 `--rerun-tasks` 或核对测试报告 |
| 出包很慢 | 多架构一起编 / 残留编译进程占内存 | 用 `-P...build.abi=arm64-v8a`；构建前清理残留进程 |

## 5. 给 AI 协作者的工作方式建议

- **先读后改**：定位实现时，先用检索确认"真实现放在哪"（见 §1.1、§1.3），再动手。
- **改动要成体系**：加一个字段/配置，通常要同时改 领域模型 → 实体 → 映射 → 迁移 → 装配点 → UI → 多语言。只改一处就是这个项目里最常见的"半成品"。
- **验证要拿证据**：不要凭"命令返回成功"下结论 —— 核对 diff、核对测试报告、核对产物哈希。
- **改检查器也要自测**：改动检查脚本后，用"已知脏样本 + 已知干净样本"各跑一遍，确认它能拦住该拦的、放行该放的。
- **大文件先看顶部注释**：本仓库有几个上千行的文件，改动前先看文件头的说明，避免误改相邻逻辑。
